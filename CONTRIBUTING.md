# Contributing

Thanks for helping. A few rules hold across sandrogekeler's repositories; a
repository's own CONTRIBUTING.md takes precedence where it has one.

- Open an issue before a large change, so the approach can be agreed first.
- One pull request per piece of work, not one per tweak. List its changes in a
  `## Changelog` section, one `- type: text` line each (`feature`, `fix`,
  `chore`, `docs`, `skip`).
- Changelog lines and pull request titles are release-notes copy: imperative,
  sentence case, no trailing period.
- Label pull requests with an `area:` label where the repository uses them, and
  with one `type:` (`feature`, `bug`, `chore`, `docs`) when there is no
  Changelog section.
- Do not commit secrets or generated output.

Security problems: see [SECURITY.md](SECURITY.md), not a public issue.
